# Todo Example: Android AppFunctions (generated)

Generated by Omnintent 0.1.0 from omnintent.json. Do not edit; regenerate instead.

Targets `androidx.appfunctions:appfunctions:1.0.0` (stable since November 18, 2026) on
Android 16 (API 36) and later. Gemini reaches these functions through Google's Connected Apps Platform
developer preview.

## Wire it up

1. Copy `src/` into your app module and merge `build.gradle.kts.snippet` into its build file.
2. Paste `AndroidManifest.snippet.xml` inside `<application>`.
3. Implement `OmnintentHandlers` with your repositories, and expose it from your Application:

   ```kotlin
   class MyApp : Application(), com.example.todoexample.omnintent.OmnintentHandlersProvider {
       override val omnintentHandlers: com.example.todoexample.omnintent.OmnintentHandlers by lazy { MyOmnintentHandlers(this) }
   }
   ```

   No dependency-injection framework is required. If you use Hilt, you can instead add
   `@AndroidEntryPoint` to the generated base class and inject your handlers.
4. Build. KSP generates the concrete service and the function schema XML.

## Safety rules applied

- AppFunctions should perform only safe tasks the user could do in your app, so destructive actions are
  generated only when the manifest opts in (`platforms.android.enabled: true`), and then with
  `isEnabled = false`. Enable them at runtime with `AppFunctionManager.setAppFunctionEnabled` only after
  your own consent UI. Payment actions are never generated for Android.
- Properties marked `internal` or `sensitive` are left out of the returned data classes.
- Agents omit optional parameters as null, zero, false or empty; the generated functions resolve manifest
  defaults in the function body.
- Not generated here: `delete_item` (destructive).
